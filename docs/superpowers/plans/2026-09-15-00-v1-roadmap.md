**Spec:** `docs/superpowers/specs/2026-09-15-neural-brush-design.md`

This roadmap decomposes the approved V1 architecture into five reviewable implementation plans. Do not start a later plan until the prior plan's completion gate passes.

## Cross-Plan Contracts

These names are stable across all plans:

- `CircuitGraph`: immutable source graph loaded from versioned browser assets.
- `ModulationLayer`: user-editable stimulation/inhibition/connection gain only.
- `BrainEngine`: deterministic simplified neural dynamics.
- `BehaviorState`: `{ turn, forward, dwell, arousal }`.
- `SensorySample`: `{ luminance, saturation, contrast, edge, motion }`.
- `FlyState`: normalized photo coordinates + heading/speed/velocity.
- `BrushFrame`: localized Smear/Saturation/Glow parameters derived from fly/behavior state.
- `BrainPresetV1`: modulation + brush + version + seed; never image content.

Data flow remains:

```text
MaleCNS source graph (immutable)
        +
ModulationLayer
        ^
        |
Edited photo -> LocalVision -> SensoryAdapter -> BrainWorker -> BehaviorState
     ^                                                        |
     |                                                        v
BrushPipeline <- BrushBehaviorMap <- FlyController/FlyPhysics
```

## Execution Rule

At execution time, use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`. Use the approved spec plus the current plan as the source of truth. Each task follows TDD and ends in a focused commit; do not batch the whole V1 into one implementation change.
